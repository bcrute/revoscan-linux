# Finding and reproducing the reliability evidence

Start with the [learning log](reliability-learning-log.md), not an old success
message or a partial replay. Its current checkpoint, complete experiment ledger
and evidence map link protocols, negative results and remaining qualification.
The [roadmap](reliability-roadmap.md) defines the release gates. An exact pilot,
complete frame acceptance, or successful unit suite is not geometric reliability.

## What each evidence bundle contains

- Protocol: the rule and full case/pair roster declared before execution.
- Plan: exact configuration, source/report hashes, original inputs and controls.
- Executing source: the precise algorithm/tool files bound to that plan.
- Verification: command, return code, logs, JUnit and source snapshots; selected
  suites are labelled as selected, not the full repository.
- Per-cell reports and companions: every offered/refused input, accepted pose,
  candidate/solver/preparation trace and original raw identity. Related companion
  reports must remain together; a base report alone can omit an intervention.
- Scores and audits: every original fixed raw comparison, whole-configuration
  disposition and declared interactions, including missing/failed checks.
- Failed attempts and corrections: retained separately, never rewritten as if
  the original attempt succeeded.
- Evidence manifest and outside-root verification: exact file inventory and
  hashes, not proof that measurements or geometry are correct.

An archived scope may be infrastructure-only or read-only diagnosis, not an
executed tracking experiment. For example, M25's conditional Stage B adapter
was prepared but not exercised on recorded qualification data; the image-normal
review fits no pose. Do not add those to completed trajectory counts.

The [official-package](firmware-package-review-20260909.md) and
[device-file](firmware-device-review-20260909.md) reviews preserve inert vendor
bytes and structural analyses separately from tracking trials. Do not run a
captured executable or device-reading driver merely to reproduce an offline
checksum. Neither bundle supplies an authenticated complete recovery image.

## Rerun without changing the record

Read the relevant protocol and final disposition first. Use a fresh, explicitly
named output directory; never pass a sealed archive as output. Many drivers
deliberately refuse an existing plan or result. Do not remove those guards to
make a rerun work. Preserve the original source/report identity before changing
anything and label new work as a new attempt or experiment.

Frozen drivers often contain absolute paths to earlier capture and comparison
roots. Moving one result directory alone is not a portable reproduction bundle.
Keep the source snapshot, original raw capture, prerequisite reports and their
manifests available; a relocated reproduction needs an explicit path mapping
and freshly bound plan. Never silently rewrite old JSON paths or hashes.

The current runtime fingerprint and native-library hashes are under
`20260909-reliability-normal-taper/`. Those records describe that execution
environment, not a lock on all future GPU drivers or historical measurements.
Exact comparison of observation controls is mandatory before attributing a
changed trajectory to a new mechanism. No package or driver installation is
necessary merely to inspect the saved evidence.

For a single M26 diagnostic cell, the opt-in entry point is
`tools/scanner_depth_median_replay.py`; its CLI requires explicit preparation,
reverse-seed, capacity, finite-update, frame count and output choices. Static
and moving framing differ. Its full campaign additionally requires twelve
exact controls and forty changed cells, not a chosen promising recording.
The separate longer/handheld Stage B remains mandatory for a whole survivor.

## Retention limits

All preservation so far is local. The repository and `/home/ben/scans/diagnostics/`
share the same filesystem; sealed hashes are not an off-machine backup. No
external backup destination has been supplied or authorized. Preserve raw
capture roots as well as diagnostics: a manifest containing a raw-file hash is
not a copy of that frame. The two historical `/tmp` preservation bundles have
explicit original-to-copy inventories; their scope is documented, not universal.
